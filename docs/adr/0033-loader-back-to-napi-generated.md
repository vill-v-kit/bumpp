# loader 回归 napi-rs 官方生成物，删除自研加载器

`napi/bumpp-core/index.js` 原为手写 loader（本地 `.node` 与平台包按序兜底、musl 探测、平台包版本强校验、加载失败列出全部支持平台的可读报错）。自研动机是 napi-rs 生成物的报错不含已支持平台清单，不满足本仓库的报错可读性要求——该决策此前只活在 `index.js` 头部注释里，无 ADR，本篇先补记再反转。

反转的导火索是 Socket.dev 供应链评分：`@vill-v/bumpp-core` Supply Chain Security 70 分，5 条能力型告警（Debug access / Dynamic require / Environment variable access / Filesystem access / URL strings）全部由手写 `index.js` 触发；`@vill-v/bumpp` 自身 0 告警被传导至 71。对照组 oxlint 的 `dist/bindings.js` 即 napi-rs 官方模板（minify），能力面更大（`createRequire` / `readFileSync` / `execSync` / env 读取俱全）却仅 1 条告警（URL strings，与自研 loader 同源的 npm#4828 链接），Supply Chain 99——Socket 官方文档确认 Supply Chain 分由包自身告警（严重度加权、上限封顶）与依赖计数构成，依赖树告警不滚入；生态几十万份同构生成物是统计上的"常见模式"，手写变体则逐能力计分。结论：消告警的最可靠路径是让文件回到与生态同构的生成物，而不是继续调优手写实现。

## Decisions

- loader 整体回归 `napi build --platform --esm` 的官方生成物，**零手写加载代码**：构建命令去掉 `--no-js` 加 `--esm`；自研 `index.js` 与 `loader.test.ts`（两个用例测的均为被删行为）删除；`index.js`/`index.d.ts` 转为 gitignore 生成物（与 ADR-0029 平台目录同一哲学），经各 napi CLI 构建腿产物捎带、publish-npm 由 `scripts/collect-artifacts.mjs` 归位 core。
- 反转原自研决策的两条行为，回到生成物默认：①加载失败不再列出支持平台清单——报错为生成物的 npm#4828 标准文案；②平台包版本强校验取消——退回生成物的 `NAPI_RS_ENFORCE_VERSION_CHECK` 门控、默认关。已知的 UX 退化：Intel Mac 等不支持平台的用户会看到"删 lockfile 重装试试"的误导性报错而非明确的平台清单——接受，换取生态同构的告警豁免与维护面归零；文档网站的平台矩阵说明仍是软着陆点。
- `--esm` 必须显式传：napi CLI 不按 package.json `type: module` 自动判定（`def/build.ts`、`build.ts` 的 `options.esm` 直读 flag），漏传会把 CJS 生成物写进 ESM 包。CI 5 条 napi 腿与本地 build 脚本同步；zigbuild 腿不经 napi CLI 不产 JS，由其余腿供给（同 ADR-0025 的 dts 供给模式，各腿生成物内容一致，merge-multiple 合并无冲突）。
- test-bindings job 从 vitest 改跑 `node napi/bumpp-core/smoke.mjs`：在真实宿主上端到端跑生成物 loader（本地 `.node` fallback 加载 → 导出面 → `cliRun` 通路 → 平台变体 bin 注入），覆盖强于被删的两个报错文案用例。
- 验收线为 `@vill-v/bumpp-core` Package Alerts ≤ 1（预期恰好 1 条 URL strings，对齐 oxlint 自身基线）：6.1.2 上架后 24h 内人工复查 socket.dev，不设 pre-publish 门禁。PR 阶段 pack/publint/tarball 断言干跑经评估不引入——本仓质量门在本地 hk 钩子（ADR-0031）+ tag 触发 CI；本地 pack 断言已手动前置验证，tag 构建即全链路验证，失败按删 tag 重推预案恢复（COL-62 先例）。

## Consequences

- 生成物内嵌构建时 package.json 版本字面量（供门控的版本校验）：tag 构建在 bump 之后执行，天然同步；本地 dev 构建内嵌当前工作区版本，无 drift 场景。
- 本地 fallback 语义微调：生成物对匹配平台**先试本地 `./bumpp-core.<triple>.node` 再试平台包**（原自研相反）——开发内循环产物即当前版本，行为等价；`NAPI_RS_NATIVE_LIBRARY_PATH` 覆盖为生成物自带第一分支，ADR-0032 的既定语义不变。
- musl 探测升级为生成物三级链（读 `/usr/bin/ldd` → `process.report` → `execSync('ldd --version')`）；musl 系统只分派 musl 三元组，旧包管理器 gnu/musl 双装场景下 gnu 包不会抢兜底（ADR-0025 语义由分派结构保证）。
- ADR-0028 的"Intel Mac 硬错误列平台清单"条款与 ADR-0029 真相源链的"loader 推导"段同步修订，修订前全文已分别归档 Linear（COL-73、COL-72）；COL-12 的验收标准反转已在该票标注。
- 若生成物仍被 Socket 打出非 URL strings 告警（"模板同构豁免"假设证伪），兜底方案是退回手写但全面静态化 require 的变体并删 env 覆盖——出现真实证据时重开评估，不预防性实施。（2026-08-15 后记：真实证据已出，评估结论为**不实施**——手写变体同样回避不了固有能力面，见末节"验收结果"。）
- 参考锚点：ADR-0029（平台包生成与注入流）、ADR-0032（core 不内置 .node 与本地 fallback）、ADR-0028（npm 渠道 Intel Mac 语义）、ADR-0017（用户可见字符串唯一英文，生成物报错天然满足）、Linear COL-78（检查方案与验收）。

## 验收结果（2026-08-15 后记）

**验收线未达成。** 6.1.2 上架 2 天后 Socket.dev 已扫描 6.1.2：`@vill-v/bumpp-core` Supply Chain Security 仍为 70，5 条能力型告警原样（Debug access / Dynamic require / Environment variable access / Filesystem access / URL strings）；`@vill-v/bumpp` 传导分 71 不变。

已排除"发错产物"：npm 实物 tarball 的 `index.js` 确为 29254B 官方生成物（`auto-generated by NAPI-RS`，ESM），5 条告警逐条对得上生成物代码——`createRequire`、`readFileSync`（musl 探测）、`process.report.getReport`（Debug access 来源）、`process.env.NAPI_RS_*`、npm#4828 URL。

结论：grill 阶段"与生态模板同构即免罚"的核心假设**证伪**。oxlint 同模板仅 1 条告警的差异待遇推测来自其 minify 产物形态或包流行度/信誉因子，不可控、不可复制，不追。能力型告警是任何 napi loader 的固有面（必须 require `.node`、必须探测 musl、必须提供 env 覆盖分支），除非放弃预编译分发，无代码层面消除手段；总分剩余扣分面为 Quality/Maintenance 的流行度因子（周下载量、包龄），随时间自然增长，非工程动作。

决策保留、不回滚：消除手写 loader 维护面、报错语义对齐生态的工程收益独立于 Socket 分成立。本 ADR 的动机一节按"消告警"陈述，实际达成的是"生态同构 + 维护面归零"，评分目标记为未实现。
