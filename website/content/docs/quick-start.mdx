## 安装

按你的环境任选一种安装方式，功能完全一致：

- **npm**（Node.js 项目首选）：`npm install -D @vill-v/bumpp`，详见[安装 · npm](/docs/install/npm)
- **cargo binstall**（免编译，推荐）：`cargo binstall vbumpp` 直接下载预编译原生 CLI，不需要 Node.js 环境，也无需本地编译
- **cargo install**：`cargo install vbumpp` 从 crates.io 拉取源码本地编译

预编译产物覆盖 macOS（Apple Silicon）、Linux（x64 / arm64，含 Alpine）、Windows（x64 / arm64）共 7 个平台，Intel Mac 等未覆盖平台会自动回退源码编译。详见[安装 · crates.io](/docs/install/crates-io)；想跟进最新未发布改动，还可以[从源码编译安装](/docs/install/cargo)。

## 第一条命令

在项目根目录（package.json 或 Cargo.toml 所在处）执行：

```sh
vbumpp
```

会出现一个交互菜单让你选择新版本怎么算：

- `patch` / `minor` / `major`：按 semver 递增
- `prepatch` / `preminor` / `premajor` / `prerelease`：发预发布版本（如 `1.1.0-beta.1`）
- `conventional`：根据自上次发版以来的 conventional commits 自动推断
- `next`：取当前版本的下一个递增
- `none`：保持当前版本不变；`custom`：手动输入版本号

选定后，工具会依次自动完成：

1. 根据最近一个 git tag 以来的提交生成变更记录，写入 `CHANGELOG.md`
2. 更新版本文件中的版本号
3. 执行你在配置里声明的发版脚本（如有）
4. git commit → 打 tag → push
5. 装了平台包（如 `@vill-v/bumpp-gitee`）或给出 `--provider` 时，在该平台创建 Release

<Callout type="info">
仓库还没有任何 git tag 时会跳过 changelog 生成。
</Callout>

## 常见用法

```sh
vbumpp                          # 标准发版
vbumpp -r                       # monorepo：递归更新整树包的版本
vbumpp package.json docs/v.txt  # 只更新指定的版本文件
vbumpp -o HISTORY.md            # changelog 写到别的文件
```
